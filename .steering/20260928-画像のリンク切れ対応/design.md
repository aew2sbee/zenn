### 原因
- 確認済みの事実

| 項目 | 結果 |
|---|---|
| 記事内の画像パス | 7件とも `/images/articles/github-branch-protection-ruleset/*.png` の絶対パス |
| 画像ファイル | 7件ともリポジトリに存在し、gitで管理されている |
| 画像の形式・サイズ | PNG、45〜70KB（Zennの制限: .png/.jpg/.jpeg/.gif/.webp、3MB以内） |
| 公開ページの画像URL | 7件とも HTTP 404 |
| 画像URLの `sha` | リポジトリの画像ファイルのgitハッシュと一致 |
| 他の移行記事（docker-desktop-install、react-install など5件） | 画像URLはすべて HTTP 200 |
| 記事の追加方法 | 記事と画像を同一コミット（907e915）で追加し、PR #39 でマージ。他の移行記事と同じ手順 |

- 推定原因: PR #39 のマージ時に、Zennへの画像アップロードが失敗した。Zennは記事側に画像の `sha` を記録したが、配信先には画像が存在しない
- 画像ファイルが変わらない限り `sha` も変わらないため、pushし直してもZennは画像を再アップロードしない
- 推定の裏付けとして、作業の流れ1でZennダッシュボードのデプロイ履歴を確認する。確認結果は本節に追記する

### 対応方法の比較

| 方法 | 内容 | 採否 |
|---|---|---|
| 画像の中身を変更する | tEXt チャンクを追加し、gitハッシュを変える | 採用。見た目・パス・本文が変わらない |
| 画像のファイル名を変更する | ファイル名と記事内のパスを変える | 不採用。記事本文の変更になり、requirements.md の制約に反する |
| 同じ内容で再push | 空コミットなどでデプロイを再実行する | 不採用。`sha` が変わらず再アップロードされない可能性がある |
