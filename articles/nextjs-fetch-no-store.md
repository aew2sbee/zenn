## 🌱 はじめに

`Next.js`の学習の為に、下記書籍を読みました。
下記書籍の`キャッシュ`について学びがあったので、執筆します。

@[card](https://gihyo.jp/book/2024/978-4-297-14061-8)

:::message alert
本記事は、書籍が対象としている **Next.js 14 の App Router**、かつ**サーバーコンポーネント内の fetch** を前提にしています。
Next.js 15 以降は fetch の既定値が変わっているため、「補足事項」もあわせて確認してください。
:::

## 🌱 結論

:::message
fetch 関数のオプションに `{ cache: 'no-store' }` を追加する

```diff ts
- fetch(`http://...`);
+ fetch(`http://...`, { cache: 'no-store' });
```

:::

> **キャッシュとは、**
> Web ページや画像、スクリプトなどのコンテンツを一時的に保存する仕組みです。
> これにより、同じページに再度アクセスするときにサーバーにリクエストを送ることなく、
> 素早くコンテンツを表示することができます。

Next.js（App Router）の場合は、サーバー側で fetch の結果を保存し（Data Cache）、以降のリクエストやビルドで再利用します。
`{ cache: 'no-store' }` を指定すると、リクエストのたびにデータを取得し直します。

## 🌱 使い分け

### 1. 動的データ

:::message
`{ cache: 'no-store' }` のオプションを**追加する**
:::
例えば、下記項目のような**変更が多いデータ**に対して有効

1. 閲覧履歴
2. 商品在庫数

### 2. 静的データ(キャッシュ)

:::message
`{ cache: 'no-store' }` のオプションを**追加しない**
:::
例えば、下記項目のような**変更が少ないデータ**に対して有効

1. 商品概要
2. ブログ記事
3. ニュース記事

なお、一定間隔で更新したいデータは、`next: { revalidate: 60 }` のように再検証する間隔（秒）を指定する方法もあります。

## 🌱 補足事項

### 1. 初期値は、キャッシュされる（Next.js 14 まで）

:::message
Next.js 14 までは、fetch 関数でオプションを指定しなければ、静的データ(キャッシュ)となる
:::

```ts
fetch(`http://...`);
```

Next.js 15 以降は既定値が変わり、オプションを指定しない fetch の結果はキャッシュされません。
15 以降でキャッシュしたい場合は、`{ cache: 'force-cache' }` を明示します。

### 2. npm run dev では正しく動作確認できない

:::message alert
開発モード（npm run dev）ではページがリクエストのたびにレンダリングされるため、本番のキャッシュの挙動を再現できない
:::
ビルド時にも以前取得した fetch の結果が再利用されるため、下記コマンドでキャッシュを削除してからビルド・起動すれば、挙動を確認できる

```bash
rm -rf .next/cache
npm run build
npm start
```
