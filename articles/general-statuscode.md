## 🌱 分類と意味

| ステータスコード |        分類        | 意味 |
| :--------------: | :----------------: | :--- |
|     100 番台     |   情報（処理中）   | 処理が継続中<br>クライアントはそのままリクエストを継続する（100 Continue）か、<br>サーバーの指示に従ってプロトコルを切り替える（101 Switching Protocols） |
|     200 番台     |        成功        | リクエストの成功 |
|     300 番台     |    リダイレクト    | 他のリソースへのリダイレクト<br>多くの場合（301/302/303/307/308）、クライアントは Location ヘッダーが示す URI へ再リクエストする<br>※304 Not Modified はリダイレクトではなく、キャッシュをそのまま使ってよいという意味 |
|     400 番台     | クライアントエラー | クライアントのリクエストに原因がある<br>リクエストの内容や認証情報などを見直せば、再送信して成功しうる |
|     500 番台     |   サーバーエラー   | サーバー側に原因がある<br>サーバー側のエラーが解消されれば、リクエストを再送信して正常な結果を受け取れる |

## 🌱 よく使われるステータスコード

| ステータスコード          | 意味                   |
| ------------------------- | ---------------------- |
| 200 OK                    | リクエスト成功         |
| 201 Created               | リソースの作成成功     |
| 301 Moved Permanently     | リソースの恒久的な移動 |
| 303 See Other             | 別 URI の参照          |
| 400 Bad Request           | リクエストの間違い     |
| 401 Unauthorized          | 認証が必要（認証情報がない、または無効） |
| 403 Forbidden             | アクセス権限がない     |
| 404 Not Found             | リソースの不在         |
| 500 Internal Server Error | サーバー内部エラー     |
| 503 Service Unavailable   | 一時的にサービスを利用できない（過負荷・メンテナンス中） |

:::message
ステータスコードの正式な定義は、現行の仕様である RFC 9110 を参照してください。日本語では MDN の解説も参考になります。

- [RFC 9110: HTTP Semantics - Status Codes](https://www.rfc-editor.org/rfc/rfc9110.html#name-status-codes)
- [HTTP レスポンスステータスコード - MDN](https://developer.mozilla.org/ja/docs/Web/HTTP/Status)
:::
