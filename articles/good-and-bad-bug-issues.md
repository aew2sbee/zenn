## 🌱 はじめに

2026年8月27日に発売された『QAエンジニア入門 〜チームで品質を高める連携のしかた』（岩崎駿 著）を読みました。
書籍のコラム「良い不具合報告、悪い不具合報告」に素敵な内容が書かれていたため、備忘録として残します。
書籍では「不具合報告」と呼んでいるものを、本記事では GitHub の`bug Issue`として扱います。

https://gihyo.jp/book/2026/978-4-297-15832-3

`bug Issue`は自分のためではなく、チームのために書くものだと気づかされたので、内容をまとめます。
以下の 8 項目は、書籍の内容をもとに筆者が整理したもので、筆者の経験も併せて記載しています。

## 🌱 結論
`bug Issue`には、下記の要素があると良いと思います。

:::message
1. 事象
2. 再現率
3. 再現手順
4. 実際の結果
5. 期待する結果
6. 環境情報
7. ユーザー影響
8. 添付資料

**タイトル**
タイトル欄にはテンプレートの記入例（HTML コメント）を置けないため、ここで補足します。タイトルには`1. 事象`をシンプルかつ簡潔に書きます。

```md
IDとパスワードを入力後に、ログインボタンが反応しない
```

**内容**
```md
## 再現率
<!-- おおよその割合で構わないので、どのくらいの頻度で発生するかを書く -->
<!-- 例) 5回に1回ぐらい発生する -->

## 再現手順
<!-- 初見の人でも再現できるように、URL・使用したアカウント・選択した項目を具体的に書く -->
<!-- パスワードやトークンそのものは書かず、配布元を参照する形にする -->

## 実際の結果
<!-- エラーメッセージやログは、検索できるようにテキストで貼る（画面の状態はスクリーンショットも添付する） -->
<!-- 添付前に、認証情報や個人情報が写り込んでいないか確認する -->

## 期待する結果
<!-- 本来どうなるべきかを書く。ここが無いと、他の人が修正方針を判断しにくい -->
<!-- 例) トップページ(https://dev.example.com)に遷移する -->

## 環境情報
<!-- アプリのバージョン、ライブラリのバージョン、OS、ブラウザなどをわかる範囲で書く -->

## ユーザー影響
<!-- 誰のどの業務にどれくらい影響するか（影響度）を書く。修正の優先順位を判断する材料になる -->
<!-- 例) 影響度: 高 -->

## 添付資料
<!-- 仕様書、関連Issue、類似事象の記事などのURLを書く -->
```

:::

## 🌱 解説
### 1. 事象
シンプルかつ簡潔に記載します。
※シンプルすぎて意味が分からないのはNG

```diff
- ログインができない
+ IDとパスワードを入力後に、ログインボタンが反応しない
```

### 2. 再現率
具体的な数字でなくても大丈夫なので、おおよその割合を記載します。
優先順位の判断や関係者への共有時に必要な情報です。

```diff
- 時々
+ 5回に1回ぐらい発生する
```

### 3. 再現手順
実際のURL、アカウント情報、選択した項目などの情報を記載します。
初見の人でも再現できるように細かく丁寧に記載します。
ただし、パスワードやトークンは書かず、配布元を参照する形にします。公開リポジトリの場合は、社内の URL も伏せてください。

```diff
- 1. ログイン画面でログインをする
+ 1. ログイン画面(https://dev.example.com/login)にアクセスする
+ 2. IDに test-user-01 を入力する
+ 3. パスワードに配布済みのテスト用パスワードを入力する
+ 4. ログインボタンを押す
```

### 4. 実際の結果
スクリーンショットやエラーメッセージ、ログなどの取得した情報を記載します。
不具合調査の時に、上記情報があると調査がしやすいです。

:::message
※エラーメッセージやログをスクリーンショットで残してくれるのはとても素晴らしいのですが、画像の文字は検索やコピーができず、調査のときに手入力で書き起こすことになる場合があります。なるべくテキストでも残しましょう。
また、貼る前にトークン・Cookie・個人情報などが含まれていないか確認し、含まれている場合はマスクしてください。
:::

```diff
- ログインできない
+ ボタンをクリックしても反応しない
+ ブラウザの開発者ツール（Console）に「XXXXXX」というエラーが出ている
```

### 5. 期待する結果
期待値を記載します。
他の人が不具合を修正する際、期待値が分からないと対応が困難になります。

```diff
- 未記載
+ トップページ(https://dev.example.com)に遷移する
```

### 6. 環境情報
アプリのバージョン、ライブラリのバージョン、OS、ブラウザなどの情報をわかる範囲で記載します。

```diff
- 未記載
+ OS: Windows 11 Pro 24H2
+ ブラウザ: Google Chrome 141.0.7390.55
```

### 7. ユーザー影響
ユーザー（利用者の業務）への影響度と、その理由を記載します。
時間的な猶予など、いつまでに直すべきか（緊急度）は、影響度とは別に書きます。

```diff
- 未記載
+ 影響度: 高（○○機能は、○○業務をする上で必要な機能のため）
+ 影響度: 低（○○機能は管理者のみが使う機能で、代替手段があるため）
+ 緊急度: 低（○○機能は夏季に集中して使われる機能であり、時間的猶予があるため）
```

### 8. 添付資料
不具合に関する参照資料や、世の中の類似事象を扱った記事のURLを記載します。

```diff
- 未記載
+ 仕様書: https://example.atlassian.net/wiki/spaces/login-spec
+ 関連Issue: #123 (3ヶ月前に発生した類似の不具合)
+ 類似事象の外部Issue: https://github.com/example/auth-library/issues/4567
```
