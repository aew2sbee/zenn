## 🌱 はじめに

この記事では、仕様書などの文章を**わかりやすく**書くコツをまとめています。
書籍『エンジニアが一生困らないドキュメント作成の基本』（仲田尚央 著、ソシム）を参考にしています。
仕様書や手順書を書くエンジニアの方に向けた記事です。

@[card](https://www.socym.co.jp/book/post-19000)

## 🌱 結論

:::message
わかりやすい文章とは、読み手にとって次の 3 つを満たす文章です。

1. 必要な情報を正しく得られる
2. 効率良く理解できる
3. 不快さがなく、ポジティブに受け止められる
:::

## 🌱 1. 必要な情報を正しく得られる

### 1. 曖昧さを排し、明確に書く

読み手によって解釈が分かれる表現を避け、数字などで明確に書きます。

```diff md:サンプル文章
# 数字で表現する
- 画面の表示が速い
+ 画面が2秒以内に表示される
```

### 2. できるだけ具体的に書く

抽象的な評価ではなく、何がどうなっているのかを具体的に書きます。

```diff md:サンプル文章
# 誰にでもわかる具体的な内容を示す
- iPhoneは簡単に使用できる
+ iPhoneは、アプリのデザインと操作に一貫性があり、
+ ユーザーが異なるアプリを共通の操作感覚で使える
```

## 🌱 2. 効率良く理解できる

読み手が少ない労力で理解できるように書きます。

### 1. 重要なことから書く

読み手は、ドキュメントを最後まで読むとは限りません。そのため、**要点を先に伝えます**。

1. **言いたいこと**
2. **その理由や説明**

### 2. 読み手の視点で書く

読み手が何をすると、どのような結果（メリット）を得られるのかを明記します。
開発者の目線で、仕組みを説明するだけにならないようにします。

```diff md:サンプル文章
# 開発者の視点
- アプリの自動アップデートを有効にすると、
- 定期的にアップデートの有無を確認し、自動的にアプリをアップデートします。
# ユーザーの視点
+ アプリの自動アップデートを有効にすると、常に最新版のアプリを使用できます。
```

### 3. 能動態と受動態を使い分ける

文の途中で主語が変わると、読みにくくなります。
後半の主語がユーザーからアプリに変わる場合は、後半を受動態にすると、主語のねじれを防げます。

```diff md:サンプル文章
# 文章全体が能動態のままで読みにくい
- アプリの自動アップデートを有効にすると、自動的にアプリをアップデートします。
# 文章の後半を受動態にして読みやすい
+ アプリの自動アップデートを有効にすると、アプリが自動的にアップデートされます。
```

### 4. 一文一義で書く

1 つの文には、1 つの内容だけを書きます。

```diff md:サンプル文章
- iPhoneはアップル社が開発し販売するスマートフォンで、シンプルで洗練.........
+ iPhoneはアップル社が開発し販売するスマートフォンです。
```

```diff md:サンプル文章
- ホーム画面で[設定]を選択し、[Wi-Fi]を選択し.........
+ 1. ホーム画面で[設定]を選択します。
+ 2. [Wi-Fi]を選択します。
+ 3. ......
```

## 🌱 3. 不快さがなく、ポジティブに受け止められる

### 1. 肯定形で書く

できないことより、できることを伝えます。

```diff md:サンプル文章
- 100件を超えるデータは登録できません。
+ 100件までデータを登録できます。
```

ただし、禁止事項はあえて否定形で書きます。

```diff md:サンプル文章
- 電源を入れたままにしてください。
+ 電源を切らないでください。
```

## 🌱 まとめ

- 曖昧さを排し、数字などで具体的に書く
- 要点を先に書き、読み手の視点で書く
- 能動態と受動態を使い分け、一文一義で書く
- 肯定形で書く（ただし、禁止事項は否定形で書く）
