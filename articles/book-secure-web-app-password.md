## 🌱 はじめに

書籍『体系的に学ぶ 安全なWebアプリケーションの作り方 第2版』（2018年刊）を読み、パスワードの安全性について学んだことをまとめます。
自分のパスワードの付け方を見直したい方に向けた記事です。

@[card](https://www.sbcr.jp/product/4797393163/)

### 結論

:::message
下記の条件を満たすと、安全性が高まります。

1. パスワードの長さを`8文字以上`にする
2. パスワードに`英字、数字、記号`をそれぞれ1文字以上含める
3. パスワードに`ユーザー情報に類似した情報`を含めない
4. パスワードに`パスワード辞書に載っていそうな単語`を含めない

:::

:::message alert
上記は書籍刊行時点（2018年）の推奨をもとにしています。
現在の NIST SP 800-63B-4 では、文字種の組み合わせを強制するルールは推奨されておらず、**長さ**と、よく使われるパスワードや漏えいしたパスワードを拒否すること（ブロックリスト）が重視されています。パスワードだけで認証する場合は、15文字以上が求められています。
パスワードマネージャーでランダムなパスワードを生成し、サービスごとに使い分けることをおすすめします。
:::

## 🌱 1. パスワードの長さを`8文字以上`にする

攻撃者は、考えられる文字の組み合わせを順番にすべて試す「総当たり攻撃（ブルートフォース攻撃）」でパスワードを特定しようとします。
組み合わせ数が多いほど、すべて試すのに時間がかかるため、パスワードを特定するのが困難になります。
組み合わせ数の計算方法は下記のとおりです。

> パスワードの組み合わせ数 = 文字の種類 ^ 文字数

`^` はべき乗を表します。例えば、10^4 = 10×10×10×10 = 1万です。

文字数が`4文字 -> 6文字 -> 8文字`と増えると、組み合わせ数も増えます。

| 文字の種類        | 4文字 | 6文字  | 8文字 |
| ----------------- | ----- | ------ | ----- |
| 数字のみ（10種類） | 1万   | 100万  | 1億   |

:::message
仮に、1秒に1回ログインを試行する場合、`1億パターン`を試すには`約3.17年`かかります。
:::

![1億秒がおよそ3.17年に相当することを示す計算式](/images/articles/secure-web-app-password/password-step00.png)

## 🌱 2. パスワードに`英字、数字、記号`をそれぞれ1文字以上含める

文字数と同様に、使う文字の種類が増えると組み合わせ数が増え、パスワードの特定が困難になります。

文字の種類は、次のように増えていきます。

- 数字のみ: 10種類
- 英小文字: 26種類
- 英数字: 62種類（英小文字26 + 英大文字26 + 数字10）
- 英数字記号: 94種類（英数字62 + 記号32）

| 文字数 | 数字のみ（10種類） | 英小文字（26種類） | 英数字（62種類） | 英数字記号（94種類） |
| ------ | ------------------ | ------------------ | ---------------- | -------------------- |
| 8文字  | 1億                | 約2千億            | 約220兆          | 約6100兆             |

:::message
仮に、1秒に1回ログインを試行する場合、`約6100兆パターン`を試すには`約1億9300万年`かかります。
（約6100兆 ÷ 1年の秒数 31,536,000 ≒ 約1億9300万）
:::

### 参考: 文字の種類と文字数ごとの組み合わせ数

| 文字の種類          | 4文字     | 6文字     | 8文字     |
| ------------------- | --------- | --------- | --------- |
| 数字のみ（10種類）   | 1万       | 100万     | 1億       |
| 英小文字（26種類）   | 約46万    | 約3億     | 約2千億   |
| 英数字（62種類）     | 約1500万  | 約570億   | 約220兆   |
| 英数字記号（94種類） | 約7800万  | 約6900億  | 約6100兆  |

:::message alert
「1秒に1回」は説明を分かりやすくするための仮定です。
流出したパスワードのハッシュ値に対する攻撃（オフライン攻撃）では、1秒に数十億回以上試せる場合があり、8文字では十分とはいえません。
また、上の表はランダムに文字を選んだ場合の値です。`Password1!` のように人が考えたパスワードは、条件を満たしていても表のような強度にはなりません。
:::

## 🌱 3. パスワードに`ユーザー情報に類似した情報`を含めない

氏名や誕生日などの本人の情報は、SNS などから他人にも調べられます。攻撃者が最初に試す候補になるため、次のような情報は含めないようにします。

1. 氏名（名前、苗字）
   - 例: yamada1234
2. 誕生日
   - 例: 19900101

電話番号やペットの名前、ユーザー ID なども同様に避けましょう。

## 🌱 4. パスワードに`パスワード辞書に載っていそうな単語`を含めない

パスワード辞書とは、よく使われるパスワードや一般的な単語を集めたリストです。
攻撃者はこのリストを上から順に試して、弱いパスワードを使っているアカウントを探します（パスワード辞書攻撃）。

例えば、次のようなパスワードは辞書に載っている可能性が高いです。

- `password`、`123456`、`qwerty`、`admin`
- 一般的な英単語に数字を付けただけのもの（例: `apple1`）
- `p@ssw0rd` のように文字をよくある形で置き換えたもの

過去に漏えいしたパスワードも辞書に含まれるため、他のサービスと同じパスワードを使い回さないようにしましょう。

## 🌱 まとめ

- パスワードは長くするほど、総当たり攻撃に強くなる
- 文字の種類を増やすと組み合わせ数は増えるが、人が考えたパスワードでは効果が限られる
- 氏名や誕生日など、本人の情報を含めない
- 辞書に載っていそうな単語や、使い回しのパスワードを使わない
