## 🌱 はじめに

AWS 上で Web サーバーを構築する方法を学習したので、その最初のステップとして、EC2 でインスタンスを作成・起動・停止する手順をまとめます。

|項目|内容|
|---|---|
|**対象者**|・AWS の EC2 について知らない方|
|**伝えたい内容**|・EC2 でキーペアを作成し、Web サーバー用のインスタンスを起動・停止する手順|
|**前提条件**|・AWS のアカウント作成済み<br>・Windows|

:::message
この記事では、インスタンスの作成・起動・停止までを扱います。SSH での接続や、nginx などの Web サーバーソフトのインストールは扱いません。
画面のスクリーンショットは、執筆時点（2023年）のものです。

## 🌱 EC2 とは

EC2（Elastic Compute Cloud）は、仮想サーバーを作成・起動・管理できる AWS のサービスです。
EC2 で作成する 1 台 1 台の仮想サーバーを「インスタンス」と呼びます。
Web サーバーは、このインスタンスの上で nginx などの Web サーバーソフトを動かして構築します。

この記事に関係する主なメリットは、次の 2 点です。

- **インスタンスが稼働している時間に応じて料金がかかる**ため、使わないときは停止してコストを抑えられる
- 用途に応じて、CPU やメモリの性能が異なる**インスタンスタイプ**を選べる（今回は無料利用枠の対象タイプを使う）

:::message alert
キーペアはリージョンごとに管理されます。作業を始める前に、画面右上のリージョン（例: 東京）を確認し、キーペアの作成とインスタンスの作成を同じリージョンで行ってください。
:::

## 🌱 キーペアの作成

キーペアは、あとで自分の PC から SSH でインスタンスにログインするときに使う鍵の組です。
公開鍵暗号方式という仕組みを使います。

- **Q: 公開鍵暗号方式とは？**
  - A: 暗号化と復号に異なる鍵（公開鍵と秘密鍵）の組み合わせを使う暗号方式です。
- **Q: パブリックキー（公開鍵）とは？**
  - A: 鍵の組のうち、他者に公開してよい鍵です。EC2 ではインスタンス側に登録されます。
- **Q: プライベートキー（秘密鍵）とは？**
  - A: 鍵の組のうち、所有者だけが保持する鍵です。手元の PC に保管し、他人と共有してはいけません。

### 1. EC2 のページに移動する

画面左上の`サービス>コンピューティング>EC2`をクリックし、EC2 のページに移動します。
上部の検索欄に「EC2」と入力しても移動できます。

![AWSコンソールのサービスメニューからEC2を選ぶ画面](/images/articles/aws-ec2-web-server/ec2-step1.png)

### 2. キーペアのページに移動する

リソースの`キーペア`をクリックします。

![EC2ダッシュボードのリソース一覧にあるキーペア](/images/articles/aws-ec2-web-server/ec2-step2.png)

### 3. キーペアを作成する

画面右上の`キーペアを作成`をクリックします。

![キーペア一覧画面のキーペアを作成ボタン](/images/articles/aws-ec2-web-server/ec2-step3.png)

### 4. キーペアを設定する

下記の項目を設定します。

1. 名前 →`任意の名前`
2. キーペアのタイプ →`RSA`
3. プライベートキーファイル形式 →`.pem`

![キーペアの名前・タイプ・ファイル形式を設定する画面](/images/articles/aws-ec2-web-server/ec2-step4.png)

- **Q: RSA（Rivest Shamir Adleman）とは？**
  - A: 非常に大きな数の素因数分解が困難であることを利用した暗号アルゴリズムです。広く使われている方式のため、今回はこちらを選びます。
- **Q: .pem とは？**
  - A: 鍵や証明書をテキストで表現するファイル形式（PEM 形式）です。Windows 標準の ssh コマンド（OpenSSH）で使えます。PuTTY を使う場合は `.ppk` を選びます。

### 5. 作成したキーペアを確認する

問題がなければ、`キーペアが正常に作成されました。`とポップアップが表示されます。
プライベートキーのファイルが自動でダウンロードされることを確認します。

![キーペアの作成成功のメッセージとダウンロードされたpemファイル](/images/articles/aws-ec2-web-server/ec2-step5.png)

:::message alert
プライベートキーをダウンロードできるのは、作成時の 1 回だけです。紛失すると再取得できないため、大切に保管してください。
:::

## 🌱 プライベートキーをローカルに配置

### 1. 作成したプライベートキーを .ssh に配置する

`C:/Users/[user_name]/`配下に`.ssh`というディレクトリを作成します。
その中に、先ほどダウンロードした`プライベートキー`を配置します。
`.ssh` は、ssh コマンドが鍵を探す慣例の置き場所です。

![エクスプローラーで.sshフォルダーにpemファイルを配置した状態](/images/articles/aws-ec2-web-server/ec2-step6.png)

## 🌱 インスタンスの設定

### 1. インスタンスを起動するページに移動する

EC2 ダッシュボードから`インスタンスを起動`をクリックします。

![EC2ダッシュボードのインスタンスを起動ボタン](/images/articles/aws-ec2-web-server/ec2-step7.png)

### 2. サーバー名を設定する

今回は、`server_for_study`という名前にします。

![インスタンスの名前にserver_for_studyを入力した画面](/images/articles/aws-ec2-web-server/ec2-step8.png)

### 3. OS を設定する

今回は、`Ubuntu Server 22.04 LTS`を選択します（執筆時点）。
現在は、より新しいバージョンも選べます。

![OSイメージとしてUbuntu Server 22.04 LTSを選択した画面](/images/articles/aws-ec2-web-server/ec2-step9.png)

### 4. インスタンスタイプを設定する

インスタンスタイプは、サーバーの性能（CPU とメモリ）の種類です。
執筆時点では、無料利用枠の対象である`t2.micro`を選択しました。

![インスタンスタイプとしてt2.microを選択した画面](/images/articles/aws-ec2-web-server/ec2-step10.png)

:::message
無料利用枠の仕組みは変わっています。2025年7月15日以降に作成したアカウントでは、t2.micro は無料利用枠の対象外で、t3.micro などが対象です。コンソールで「無料利用枠の対象」と表示されるタイプを選んでください。
:::

### 5. キーペアを設定する

先ほど作成した`キーペア`を選択します。

![キーペア名に作成したキーペアを選択した画面](/images/articles/aws-ec2-web-server/ec2-step11.png)

### 6. ネットワークを設定する

ネットワーク設定では、インスタンスへの通信の許可ルール（セキュリティグループ）を作成します。
ブラウザから Web サーバーにアクセスできるように、下記の項目にチェックを付けます。

- インターネットからの HTTPS トラフィックを許可
- インターネットからの HTTP トラフィックを許可

![ネットワーク設定でHTTPとHTTPSのトラフィックを許可した画面](/images/articles/aws-ec2-web-server/ec2-step12.png)

:::message alert
画像では、SSH トラフィックの許可元が「任意の場所（0.0.0.0/0）」になっており、SSH がインターネット全体に開いた状態です。
SSH の許可元は「自分の IP」に絞ることをおすすめします。
:::

### 7. ストレージを設定する

ストレージは、OS やファイルを保存するディスク（EBS）です。
今回は勉強用で料金を抑えたいため、`8GiB`に設定します。

![ストレージを8GiBに設定した画面](/images/articles/aws-ec2-web-server/ec2-step13.png)

## 🌱 インスタンスの起動/停止

### 1. インスタンスを起動する

各種設定が完了したので、`インスタンスを起動`をクリックします。

![設定画面の最下部にあるインスタンスを起動ボタン](/images/articles/aws-ec2-web-server/ec2-step14.png)

ロード画面の後に`成功`のポップアップが表示されれば OK です。
インスタンス一覧で、インスタンスの状態が`実行中`になることを確認します。

![インスタンスの起動に成功したことを示すメッセージ](/images/articles/aws-ec2-web-server/ec2-step15.png)

### 2. インスタンスを停止する

インスタンスの利用料金を止めるには、インスタンスを停止します。
対象のインスタンスにチェックを付け、`インスタンスの状態` > `インスタンスを停止` を選択します。

![インスタンスの状態メニューからインスタンスを停止を選ぶ画面](/images/articles/aws-ec2-web-server/ec2-step16.png)

ポップアップの停止ボタンをクリックし、少し時間がたつと、インスタンスの状態が`停止済み`に変わります。

![インスタンスの状態が停止済みになった画面](/images/articles/aws-ec2-web-server/ec2-step17.png)

:::message alert
以前、インスタンスを停止し忘れて 2 か月放置し、5 千円ほどの料金が発生したことがあります。
**インスタンスが実行中の間は料金が発生します。必要なときだけ起動してください。**

また、停止中もストレージ（EBS）の料金は発生します。学習が終わって不要になったら、`インスタンスの状態` > `インスタンスを終了` でインスタンスを削除してください。
:::

## 🌱 まとめ

- キーペアを作成し、プライベートキーを `.ssh` フォルダーに配置した
- OS・インスタンスタイプ・ネットワーク・ストレージを設定し、インスタンスを起動した
- 使わないときはインスタンスを停止し、不要になったら終了（削除）する

次のステップとして、SSH でインスタンスに接続し、nginx などの Web サーバーソフトをインストールします。
