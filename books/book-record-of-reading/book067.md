## 🌱 読書メモ

### 📌 シェルスクリプトの利点とは？
- 自動化
- 高移植性
- オペミス防止

::::details 🤖 Claude に相談した内容
- **自動化**: 繰り返し行う作業をスクリプトにまとめて、コマンド1つで実行できる
- **高移植性**: UNIX系の環境（macOSやUbuntuなど）であれば、同じスクリプトをほぼそのまま動かせる
- **オペミス防止**: 手順をスクリプトに書いておくことで、手作業による入力ミスや手順の抜け漏れを防げる
::::

### 📌 シェルスクリプトを採用しないほうがいいケースとは？
- 処理速度を求められるケース
- 100行以上に肥大化するケース

::::details 🤖 Claude に相談した内容
- **処理速度を求められるケース**: 外部コマンドを何度も起動するため、速度が必要な処理には向かない
- **100行以上に肥大化するケース**: 行数が増えると読みづらく保守しにくくなるため、PythonやGoなどに切り替える目安になる
::::

### 📌 tmuxとは？
tmux（ティーマックス）は、1つのターミナルの中で複数の仮想ターミナルを扱えるようにするツール。

::::details 🤖 Claude に相談した内容
tmux はターミナルマルチプレクサと呼ばれる。

- **セッションの維持**: 接続が切れても、中で動いている処理は止まらない。SSHで接続したサーバーで長い処理を動かしている最中にネットワークが切れても、再接続して `tmux attach` で元の画面に戻れる
- **画面分割**: 1つのウィンドウを縦や横に分けて、複数のコマンドを並べて見られる
- **ウィンドウ（タブ）切り替え**: 1つのターミナルで複数の作業画面を切り替えられる
- **デタッチとアタッチ**: 作業画面をいったん離れ（デタッチ）、あとで戻る（アタッチ）ことができる

用語は次のとおり。

| 用語 | 意味 |
| --- | --- |
| セッション | tmux の作業単位 |
| ウィンドウ | セッション内のタブのようなもの |
| ペイン | ウィンドウを分割した1区画 |

```bash
tmux                  # 新しいセッションを開始
tmux new -s 名前      # 名前を付けて開始
tmux ls               # セッション一覧
tmux attach -t 名前   # セッションに戻る
```

操作は、プレフィックスキー（既定は `Ctrl+b`）を押してからキーを押す。たとえば `Ctrl+b` のあとに `d` でデタッチ、`%` で左右分割、`"` で上下分割になる。

tmux が役に立つ主な場面は次のとおり。

- **リモートサーバーで長い処理を動かすとき**: ビルド、バックアップ、データ移行、大きなファイルの転送など。tmux の中で実行しておけば、SSH が切れたりノートPCを閉じたりしても処理は続く。あとで `tmux attach` で戻って結果を確認できる
- **複数の作業を同時に見たいとき**: 左でログを `tail -f` で流し、右でコマンドを実行する、といった使い方。開発サーバー、テスト、エディタを1画面に並べることもある
- **作業環境をそのまま残したいとき**: セッションを残しておけば、翌日も同じ画面構成・同じディレクトリから再開できる
- **ターミナルのタブを使えない環境のとき**: SSH 接続だけのサーバーや、タブ機能のない端末でも、ウィンドウやペインを切り替えられる
- **ペアでの共同作業**: 同じセッションに複数人がアタッチすれば、同じ画面を一緒に見ながら作業できる

GCP の Cloud Workstations のように、リモートのマシン上で普段作業している場合にも使える。ブラウザのタブやネットワークが切れても、tmux の中で動かした処理は続く。ただしワークステーションにはアイドルタイムアウトがあり、停止するとマシンごと止まるため、tmux の中の処理も終わる。tmux が守れるのは接続が切れた場合までで、ワークステーションが停止した場合は守れない。

ローカルのPCだけで作業していて、ターミナルアプリにタブや分割機能がある場合は必須ではない。
::::

### 📌 GitHub ActionsのCI/CDでもシェルが使われる
::::details 🤖 Claude に相談した内容
ワークフローの `run:` に書いたコマンドは、ランナー上のシェルで実行される。LinuxとmacOSのランナーでは既定のシェルがbashなので、ビルド、テスト、デプロイなどの手順にシェルスクリプトの知識がそのまま活きる。

```yaml
steps:
  - uses: actions/checkout@v4
  - name: ビルドとテスト
    run: |
      npm ci
      npm run build
      npm test
```

`run:` の中で `|` を使うと複数行のコマンドを書ける。長くなる場合は、スクリプトをファイルに切り出して `run: ./scripts/deploy.sh` のように呼び出す方法もある。
::::

### 📌 dotfilesとは？
dotfiles は、ホームディレクトリにある設定ファイルの総称。

::::details 🤖 Claude に相談した内容
ファイル名が `.`（ドット）で始まるため、dotfiles と呼ばれる。通常の `ls` では表示されず、`ls -a` で見られる。

| ファイル | 役割 |
| --- | --- |
| `~/.bashrc` | bash の設定（エイリアス、環境変数、プロンプトなど） |
| `~/.zshrc` | zsh の設定（macOS の既定シェル） |
| `~/.bash_profile` / `~/.profile` | ログイン時に読まれる設定 |
| `~/.gitconfig` | Git のユーザー名やエイリアスなどの設定 |
| `~/.vimrc` | Vim の設定 |
| `~/.tmux.conf` | tmux の設定 |
| `~/.ssh/config` | SSH 接続先ごとの設定 |

エイリアス（短縮コマンド）などの設定は、bash なら `~/.bashrc`、zsh なら `~/.zshrc` に書く。シェルを起動するたびに読み込まれるので、新しくターミナルを開いても毎回使える。

```bash
# ~/.bashrc の末尾に追記
alias gs='git status'
alias ll='ls -la'
```

書いたあとは `source ~/.bashrc` で今開いているターミナルに反映するか、ターミナルを開き直す。ターミナルに直接 `alias` を打っただけでは、そのターミナルを閉じると消える。使っているシェルは `echo $SHELL` で確認できる。

dotfiles を管理する理由は次のとおり。

- 新しいPCや新しいワークステーションでも、同じ環境をすぐ再現できる
- 設定の変更履歴を Git で残せるので、壊れても戻せる
- 複数のマシンで設定を揃えられる

よくある管理方法は次のとおり。

1. dotfiles 用の Git リポジトリ（例: `~/dotfiles`）を作り、設定ファイルをその中に置く
2. ホームディレクトリには、シンボリックリンク（`ln -s`）で張る
3. 設定ファイルを一括で張るセットアップ用のシェルスクリプトを用意しておく

```bash
ln -s ~/dotfiles/.bashrc ~/.bashrc
ln -s ~/dotfiles/.gitconfig ~/.gitconfig
```

:::message alert
公開リポジトリに置く場合は、APIキー、トークン、パスワードを含めないこと。`.ssh/` の秘密鍵も同様。秘密情報は設定ファイルから分けて、別に管理する。
:::
