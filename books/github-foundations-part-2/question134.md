## Q134: GitHub のシークレットスキャンについて最も適切なものはどれですか？

### 選択肢

- Issue をスキャンして未検証の認証情報を探し、自動的に削除する機能
- リポジトリのシークレットを GitHub にプッシュする前に暗号化する機能
- コード上でサードパーティのパスワードマネージャーを実行し、シークレットを安全に保存する機能
- 機密データの偶発的な漏えいを防ぐために、既知のシークレット形式をリポジトリから検索する機能

### 回答欄

:::details 回答を見る
[公式ドキュメント](https://docs.github.com/ja/code-security/secret-scanning/introduction/about-secret-scanning)

- [ ] Issue をスキャンして未検証の認証情報を探し、自動的に削除する機能（シークレットスキャンは何かを自動的に削除するのではなく、漏えいした可能性のあるシークレットを検出します。）
- [ ] リポジトリのシークレットを GitHub にプッシュする前に暗号化する機能（GitHub Actions のシークレットは暗号化を扱いますが、シークレットスキャンとは別の機能です。）
- [ ] コード上でサードパーティのパスワードマネージャーを実行し、シークレットを安全に保存する機能
- [x] 機密データの偶発的な漏えいを防ぐために、既知のシークレット形式をリポジトリから検索する機能（シークレットスキャンは、トークン、キー、その他の認証情報を検出し、漏えいを防ぐのに役立ちます。）

:::
